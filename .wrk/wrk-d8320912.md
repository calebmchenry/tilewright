## Outcome

Make layers usable for separate terrain, walls, furniture, and other map content.

## Source and scope

**Source:** INTENT.md — Map use and meaning; INTENT.md — First-version scope; INTENT.md — Remaining implementation decisions.

**Execution order:** 13 of 54. Phase: painting.

**Prerequisite:** [wrk-20574578](wrk-20574578.md) — TW-012: Add fixed-size map creation and explicit canvas growth.

This is an intentionally sequential delivery backlog. The dependency includes earlier prerequisites transitively; complete it before starting this ticket.

Implementation details left open by INTENT.md are decisions to document, not additional confirmed user requirements.

## Work

- Choose and document a minimal conventional layer-management policy, including empty-document/default-layer and last-layer behavior.
- Implement add, rename, reorder, visibility, active-layer selection, and safe removal controls using stable IDs.
- Route content-affecting layer operations through document history and rendering notifications.

## Acceptance criteria

- [ ] Terrain and buildings can be edited independently; current active layer and stack order are clear.
- [ ] Renaming/reordering never loses tiles or registry associations, and hidden underlying content remains stored.
- [ ] Removing a populated layer has deliberate user feedback and is undoable with its content and ordering restored.
- [ ] A valid active-layer target exists after management operations; visibility behavior for drawing and selection is documented.

## Validation

- Test lifecycle and undo/redo for populated layers, including active-layer removal and reorder.
- Compare overlap rendering before/after visibility changes without destroying hidden data.

Record the implementation/decision location and actual validation evidence in this ticket before marking it done.
