### Implementation locations

1. Browser build and validation: package.json adds build:web, preview:web,
   test:web and format:check:web. vite.web.config.ts preserves vite.config.ts
   while requiring scripts/web-base.ts's explicit same-origin base, selecting
   only index.html and writing clean dist-web/ output without public copying.
   .gitignore excludes that output. tsconfig.json checks the new configurations.
   scripts/preview-web.ts serves only built files at the selected prefix, refuses
   mismatched build/preview bases, and returns real 404s outside the mount or for
   missing files. It is local tooling, not a deployed application server.
2. playwright.web.config.ts and tests/web/production.spec.ts verify every emitted
   file's bytes/MIME, missing/source/harness paths, module loading of all lazy
   chunks (including Tauri and Pixi's worker environment), WebGL browser startup,
   no native startup/IPC, canonical .tilewright import/download, layer editing,
   undo, agent export, local-only requests and reload. playwright.config.ts keeps
   these production checks separate from the development UI suite.
3. .github/workflows/pages.yml is workflow_dispatch-only; base is explicit and
   deploy defaults false. Ubuntu uses .nvmrc, npm ci, Chromium, formatting,
   desktop frontend bundling (without Rust), full domain/UI tests and production
   smoke at both /pages-smoke/ and the final input base before artifact upload.
   The dependent deploy job alone has Pages/OIDC write permissions, uses the
   github-pages environment, requires PAGES_DEPLOY_ENABLED=true, reads existing
   Pages configuration without enabling it, verifies its base_path, then deploys
   the validated artifact. Concurrency does not cancel an active deployment.
   Official checkout 7.0.1, setup-node 7.1.0, configure-pages 6.0.0,
   upload-pages-artifact 5.0.0, deploy-pages 5.0.1 and upload-artifact 7.0.0
   are pinned to verified release commit hashes.
4. docs/github-pages.md and README.md describe the pinned clean build, separate
   desktop output, subpath/root/custom-domain choices, production smoke and
   limitations, manual validation/deployment, Pages Source=GitHub Actions,
   environment/branch/readiness setup for TW-062, logs/artifacts and repeatable
   rebuild/redeploy/rollback steps. No application backend or secrets are added.
