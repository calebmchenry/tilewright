## Outcome

Represent large editable maps without allocating every tile position in every layer.

## Work

- Implement document bounds, stable layer identities and order, sparse chunk-based tile storage, and deterministic iteration.
- Represent empty cells separately from arbitrary colors and registered-color references; reserve stable registry and annotation identities.
- Expose bounded read/write/batch APIs and change notifications suitable for history, rendering, and serialization.

## Acceptance criteria

- [x] A 6,400 by 6,400 map can be created with sparse allocation; memory tracks stored content rather than the full empty matrix.
- [x] Layers preserve underlying content independently of visual compositing and use stable IDs across renaming/reordering.
- [x] Cell APIs enforce integer coordinates and document bounds, and operate correctly across 64-tile visual boundaries and storage partitions.
- [x] The model is usable without React, the DOM, PixiJS, or Tauri; raw colors and registered associations cannot be confused.

### Acceptance evidence

1. **Sparse target scale:** a four-layer 6,400 by 6,400 empty document has zero
   allocated partitions, zero typed-array bytes, and zero palette entries.
   Reads/clears of empty cells allocate nothing; growth changes bounds only.
   Populated fixtures allocate only occupied partitions (measurements below).
   Sparse partitions promote at 128 occupied cells to 4 KiB arrays, demote at 64,
   and disappear when empty. Tests verify promotion/demotion and repeated erasure.
2. **Independent stable layers:** overlapping terrain/building/furniture/canopy
   cells survive full fixture loading/readback; clear affects only its layer.
   Tests verify renaming/reordering preserve IDs, associations, and underlying
   cells; duplicate names are valid and duplicate IDs are rejected.
3. **Bounded exact cells:** tests reject fractional, nonfinite, unsafe and outside
   coordinates, unknown layers, invalid paints, lengths and overflow. Tests cross
   both 32-tile storage and 64-tile visual boundaries in positive and negative
   space, cover custom partial edges and both safe-integer extremes. Entire
   batches validate before any mutation; late invalid input and throwing/reentrant
   generators leave content/version/allocation unchanged.
4. **Portable domain and distinct meaning:** model runs in Node without React,
   DOM, PixiJS or Tauri; the no-DOM TypeScript configuration passes. Raw RGBA and
   stable registry references are discriminated types, and identity namespaces
   have compile-time negative checks. Black and transparent raw paint are occupied;
   only null means empty. Annotations have reserved identities without inventing
   their later geometry or management implementation.

Notifications identify affected layer/world spans and carry immutable before/after
values. Reverse replay restores overlapping writes across layers/partitions.
Listeners observe completed batches; failures are returned without hiding commits
or preventing other listeners. Snapshots reject external mutation. Enumeration is
insertion-independent and fails on intervening mutations; it is a synchronous
read seam rather than an asynchronous save snapshot. Full command/history and
saved-state behavior remain TW-005, as intended. TW-005 was read for this handoff
only; no other ticket was changed.

### Actual model measurements

Each sample is a fresh Node process with the full real document. Initialization
includes constructor, generation, validation, writes, and temporary change records
in batches of 512 runs. It excludes the later complete readback/hash validation.
GC is outside the timer. Retained memory is post-GC `heapUsed + arrayBuffers`
minus the pre-load snapshot, including runtime/JIT overhead; it approximates model
memory, not total app physical footprint. External memory is not added again
because it includes ArrayBuffers. RSS is the whole Node process. Two samples
are baseline evidence, not percentile performance gates.

| Input | Occupied layer cells | Allocated partitions | Typed-array bytes | Initialization ms (two runs) | Retained heap + buffers MiB (two runs) |
| --- | ---: | ---: | ---: | --- | --- |
| empty | 0 | 0 | 0 | 0.16 / 0.14 | 0.0060 / 0.0044 |
| frontier-v1 | 6,620,700 | 11,193 | 32,292,864 | 328.67 / 308.96 | 37.4316 / 37.4291 |
| heartland-v1 | 24,025,200 | 35,021 | 123,985,920 | 1090.16 / 1070.68 | 135.0297 / 135.0297 |

Full-model readback + golden validation times were **433.69 / 418.39 ms** for
frontier and **871.96 / 857.35 ms** for heartland. Initialization process max RSS
was **154.16 / 163.50 MiB** and **292.42 / 289.28 MiB**, respectively; these are
whole-process high-water marks, not model-only memory. Each populated model has
six live paint entries. Exact per-layer partitions/counts and raw snapshots are
in the JSON report.
