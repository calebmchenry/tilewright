## Outcome

Continuously preserve recoverable committed work at the chosen cadence.

## Source and scope

**Source:** INTENT.md — Local operation; INTENT.md — First-version success criteria.

**Execution order:** 40 of 54. Phase: recovery.

**Prerequisite:** [wrk-dbdc0004](wrk-dbdc0004.md) — TW-039: Define recovery cadence, identity, retention, and restore policy.

This is an intentionally sequential delivery backlog. The dependency includes earlier prerequisites transitively; complete it before starting this ticket.

Implementation details left open by INTENT.md are decisions to document, not additional confirmed user requirements.

## Work

- Implement revision-aware recovery scheduling, coherent snapshot encoding, and atomic local writes using shared codec/I/O primitives.
- Keep recovery storage separate from user-chosen project paths and account for untitled/saved identities.
- Handle in-flight saves, document switches, failures, cleanup, and bounded retention.

## Acceptance criteria

- [ ] Unsaved edits produce valid recovery data while the explicit project file remains byte-for-byte unchanged.
- [ ] Partial/canceled writes cannot replace the last valid recovery snapshot.
- [ ] A delayed snapshot cannot overwrite newer recovery state or become attached to the wrong document.
- [ ] Recovery does not mark the document clean, add undo entries, or disrupt the documented responsiveness budget.

## Validation

- Use controlled clocks and injected I/O failures to test cadence, concurrency, and retention.
- Modify a saved and an untitled project, inspect recovery revisions, and compare the original project file bytes.

Record the implementation/decision location and actual validation evidence in this ticket before marking it done.
