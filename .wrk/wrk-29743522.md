Provide a simple, predictable log location for monitoring the sequential Codex ticket runner: run/ticket starts, periodic working heartbeats, ticket completions, failures, and final outcome. Reuse WRK logging where possible, preserve detailed per-ticket output and error propagation, and document how to tail the log. Validate using temporary WRK projects without starting the real backlog.

## Implementation

- scripts/run-tickets.sh now appends console progress to .wrk-runs/monitor.log across restarts and records UTC runner start/stop timestamps plus final exit status.
- Uses WRK lifecycle output for ticket START, RUNNING, OK, errors, and final queue diagnostics, with a 30-second heartbeat configurable through WRK_HEARTBEAT_INTERVAL.
- Detailed Codex output remains in WRK per-ticket stdout/stderr logs; structured timestamped events remain in each run.jsonl. Removed verbose child-output mirroring so the monitor log stays focused on progress.
- Uses tee with interrupt handling so Ctrl-C still permits the exit status to be logged.
- README.md documents tail -F, heartbeat configuration, detailed log locations, and heartbeat interpretation.

## Validation evidence

- bash -n scripts/run-tickets.sh and whitespace checks passed; wrk validate passed.
- Integration checks used real WRK in temporary projects and a stand-in Codex executable. Confirmed live log writes before completion, ordered starts/completions through a dependency chain, repeated heartbeat events and last-output age, terminal/log mirroring, and detailed output retained separately.
- Confirmed reruns append to the existing monitor log; command failure, unfinished ticket, blocked queue, and missing skill stay nonzero and record their outcomes.
- Sent SIGINT to the running process group: the active run stopped and monitor.log recorded exit 130.
- No real backlog execution was started.
