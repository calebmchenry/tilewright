## Outcome

Remove tile content and reuse colors without losing registered meaning.

## Source and scope

**Source:** INTENT.md — Drawing and rearranging; INTENT.md — Map use and meaning.

**Execution order:** 20 of 54. Phase: painting.

**Prerequisite:** [wrk-8e1860da](wrk-8e1860da.md) — TW-019: Implement the adjustable-size pencil.

This is an intentionally sequential delivery backlog. The dependency includes earlier prerequisites transitively; complete it before starting this ticket.

Implementation details left open by INTENT.md are decisions to document, not additional confirmed user requirements.

## Work

- Implement erasing through the drawing gesture pipeline with clear brush behavior.
- Choose and document eyedropper sampling rules for active versus visible composite layers and empty cells.
- Sample a tile into either its existing registry association or a raw paint color, preserving semantic identity.

## Acceptance criteria

- [x] Erasing clears active-layer cells to empty and reveals underlying content; it does not paint a background-colored tile.
- [x] Erase strokes are atomic and undo restores exactly the removed content.
- [x] Sampling registered grass selects the grass entry so later paint follows future recolors.
- [x] Sampling raw/empty/hidden-layer cases follows the documented rule without mutating the document.

## Validation

- Test erase across boundaries and overlapping layers, followed by undo/redo.
- Sample registered and unregistered colors, paint with them, then recolor the entry to verify identity behavior.

Record the implementation/decision location and actual validation evidence in this ticket before marking it done.

## Final implementation and acceptance audit — 2026-11-18

All phases and all four acceptance criteria are complete. No separate sprint
ledger/document, workers, second Codex process, or next-ticket work was used.

Implementation locations:

- `src/editor/pencil.ts`: common square-brush factory and shipping `eraserTool`.
  Uses the Pencil 1–32 square footprint, even-size below/right anchor and exact
  interpolated/clipped strokes, with `null` values. Both share the transient size
  preference. The existing drawing/history/renderer pipeline stages and renders
  the red footprint and commits one atomic Eraser command.
- `src/editor/sampling.ts`: pure bounded top-to-bottom visible-layer cell query.
  `src/editor/session.ts`: eraser registration, transient identity-aware sampling,
  readiness/overview gates, E/D shortcuts and shared bracket-size routing.
- `src/editor/navigation.ts`: one primary unmodified pointer-down samples, with
  existing navigation priority and target guards. No gesture/history is opened
  for the eyedropper. `src/App.tsx` and `src/MapCanvas.tsx`: enabled/pressed tool
  controls, readiness subscription, shared size selector and policy/shortcut help.
- `tests/domain/eraser-sampling.test.ts`: five new domain cases.
  `tests/eraser-sampling.spec.ts`: five real-canvas browser cases using shipping
  tools. `tests/editor-harness.tsx` adds their fixture route without test adapters;
  `tests/editor.spec.ts` expects the newly available tools and checks Fill's
  remaining unavailable explanation.
- Decisions and coverage: `docs/drawing-gestures.md#eraser-and-eyedropper-tw-020`,
  linked from README and clarified in `docs/color-selection.md` / `docs/layers.md`.

Acceptance evidence:

1. Erasing writes absence only on the captured active visible layer. Domain
   strokes cross signed 32-cell storage / 64-cell visual boundaries, partial
   map corners, mixed registered/raw/background-colored cells and overlapping
   terrain. Every lower-layer run and the fixed bounds are preserved. Browser
   tests at DPR 1 and 2 erase all upper content across x=64 and compare the whole
   resulting canvas byte-for-byte with the previously captured lower-only view.
2. Strokes produce one document event/invalidation and one Eraser undo step.
   Staging/hover do not change content, version, history or checkpoints. Undo
   restores complete original runs and exact canvas pixels; redo restores the
   erased result. Empty/outside erasing and size/visibility cancellation preserve
   content/redo. The common pipeline retains existing pointer capture, clipping,
   context cancellation and cache invalidation behavior.
3. Sampling Grass selects its existing RegistryId; subsequent Pencil paint stores
   that ID. A raw cell with identical green bytes remains raw when sampled and
   painted. Domain and real UI tests recolor Grass, check stored values and
   selected swatches, and confirm through tile-center screenshots that only the
   registered painted tile changes. Recolor undo/redo retains the distinction.
4. Sampling chooses the topmost occupied visible stored cell, independently of
   the active target. Hidden layers are skipped; empty upper cells expose lower
   content. All-empty/all-hidden/outside samples keep paint unchanged. Readiness
   and overview gates, reordering, hidden active targets, raw background color,
   text/modifier/secondary-pointer input and navigation priority are covered.
   Document runs, metadata, version, history, checkpoints and invalidation counts
   remain unchanged by sampling. Legacy nonopaque raw cells and invalid registry
   records report validation errors without flattening, repairing, or sampling
   an unrelated lower identity. This explicitly documents the existing opaque
   authoring boundary rather than introducing transparency controls.
