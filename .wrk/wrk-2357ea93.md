## Outcome

Allow freeform pixel-editor-style painting without requiring registered tile types.

## Source and scope

**Source:** INTENT.md — Map use and meaning; INTENT.md — Drawing and rearranging.

**Execution order:** 14 of 54. Phase: painting.

**Prerequisite:** [wrk-d8320912](wrk-d8320912.md) — TW-013: Implement layer creation, naming, ordering, visibility, and removal.

This is an intentionally sequential delivery backlog. The dependency includes earlier prerequisites transitively; complete it before starting this ticket.

Implementation details left open by INTENT.md are decisions to document, not additional confirmed user requirements.

## Work

- Implement a color picker and editable numeric/hex color input with a validated canonical color representation.
- Keep current paint color separate from registration and support choosing raw colors absent from the registry.
- Document opacity/color-space decisions consistent with solid-colored cells and a distinct empty state.

## Acceptance criteria

- [x] Any supported arbitrary color can be chosen without first creating a registry entry.
- [x] Equivalent input representations normalize consistently and invalid input does not corrupt the current paint state.
- [x] Empty cells are not encoded as an ordinary paint color; erasing can reveal lower layers.
- [x] The UI clearly indicates the currently selected color and whether it is associated with a named entry.

## Validation

- Test color normalization, invalid inputs, empty-vs-painted distinction, and selected-color state.
- Use several unregistered shades, including visually similar grays, in a rendered fixture.

Record the implementation/decision location and actual validation evidence in this ticket before marking it done.

Acceptance evidence:

- Arbitrary selection: every opaque 8-bit sRGB color is supported without a
  registry entry. Picker, hex and decimal RGB input converge on lowercase
  `#rrggbbff`. Tests cover #AbC / #ABCF / #AABBCC / #AABBCCFF / (170,187,204), all
  256 grayscale levels, black/white, and RGB boundaries. Matching a registry
  entry does not turn raw paint into a registered reference or modify entries.
- Invalid input: malformed hex, nonopaque alpha, blank/negative/fractional/
  out-of-range/exponential RGB, and malformed runtime inputs are rejected.
  Browser tests prove the last selected color/readout/picker and exact document,
  registry and history snapshots remain unchanged. Equivalent valid submission
  resets drafts/errors even when no store notification occurs. Text undo/arrows
  stay within numeric fields and cannot undo a map edit or pan the view.
- Empty versus painted: `null` remains the only empty cell. Black, white,
  background-colored paint and legacy zero-alpha raw paint remain occupied.
  Domain tests erase only the upper layer and restore exact runs through undo.
  WebGL detail (12 CSS px/tile) and cached overview (1 CSS px/tile), at DPR 1/2,
  show #808080 as [128,128,128,255], #818181 as [129,129,129,255], selected RGB
  (130,130,130) as [130,130,130,255], and erased upper swatches reveal unchanged
  terrain [51,92,70,255]. Black, white, #1d2732 map-background paint, orange and
  teal are also checked exactly. Undo/redo restores pixels and full source runs;
  the fixture registry remains empty throughout rendering tests.
- Current meaning: the visible swatch and exact hex output identify selected
  paint. The panel explicitly says Raw color / Not linked to a named entry and
  shows either Unregistered / No named match or exact matching entry names.
  Tests update a matching entry through rename, recolor, undo and deletion and
  verify the raw selection never changes. Registry adoption, collision rules,
  future-stroke identity and registry editing remain TW-015/TW-016, without an
  implicit equality-based association introduced here.

Opacity/color-space choices are documented implementation decisions: authoring
uses opaque 8-bit sRGB, accepts fully opaque shorthand/eight-digit hex, and does
not expose transparency or wider gamut controls. Existing low-level RGBA data
and rendering alpha behavior are preserved. Pencil/eraser gestures remain their
existing drawing-tool tickets; this ticket validates their selected-paint and
null-erasure command seams, not an unimplemented gesture UI.
